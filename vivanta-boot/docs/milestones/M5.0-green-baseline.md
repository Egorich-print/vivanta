# 3. G2 — PHYSICAL OWNERSHIP + RECLAMATION

Главный memory invariant:

```text
allocated_frames + free_frames == managed_frames
```

Он должен быть истинным на каждом наблюдаемом состоянии.

Lifecycle:

```text
spawn
→ allocation
→ execution
→ exit
→ cleanup
→ deallocation
→ free == baseline
```

## 3.1 PMM

Сейчас PMM фактически управляет примерно:

```text
1 MiB / 512 MiB
```

Причина:

```text
lib.rs:108
available.iter().next()
```

Исправить discovery/initialization так, чтобы использовались **все usable memory regions**.

Не предполагать, что `discover()` возвращает один регион.

Известно:

```text
discover() реально возвращает 2 региона
```

---

## 3.2 Allocation contract

Запрещена неявная семантика:

```text
allocate(n)
→ p
→ assume p + PAGE
→ assume p + 2*PAGE
...
```

Если API возвращает contiguous allocation, это должно быть **явно гарантировано**.

Предпочтительный контракт:

```rust
allocate_frame()
allocate_contiguous(n)
```

где:

```text
allocate_frame()
    → one arbitrary free frame


allocate_contiguous(n)
    → N physically contiguous frames
```

Если архитектура требует scatter allocation — реализуй отдельный scatter API.

Не маскируй проблему документацией.

---

## 3.3 MemoryObject

`MemoryObject` должен реально владеть ресурсом.

Необходимо:

```text
impl Drop
    ↓
backend.deallocate(...)
```

Проверить `revoke()`.

`revoke()` не должен только очищать:

```text
mappings[]
```

Он должен приводить ownership state к корректному lifecycle state.

## 3.5 MappingSet

## 3.6 Mapping atomicity

В:


сейчас MMU может программироваться **до успешной вставки mapping в MappingSet**.

Это запрещено.

Нужно обеспечить transactional ordering:

После ошибки не должно существовать:

```text

```

# 5. EL0 FAULT CONTAINMENT

Сейчас ADR-019 формально санкционирует:

```text
elr += 4
```

для EL0 synchronous exception.

Это необходимо удалить.

Нельзя:

```text
fault
→ skip instruction
→ continue execution
```

Целевая семантика:

```text
EL0 fault
    ↓
identify current ThreadId
    ↓
terminate current task
    ↓
release task resources
    ↓
reclaim memory
    ↓
scheduler selects next runnable thread
```

После fault другого потока:

```text
other threads continue
```

Fault одного task не должен:

* ломать scheduler;
* corrupt PMM;
* оставлять mappings;
* оставлять stack;
* оставлять heap allocations;
* убивать kernel.
