# M4.5.0 — EL0 Preparation (Complete)

> **Status:** ✅ Complete
> **Tag:** `M4.5.0-el0-preparation`
> **Commits:** `25301eb` (M4.5.0 implementation)
> **Date:** 2026-07-17
> **Platform:** QEMU AArch64 (`-M virt -cpu cortex-a53`)

## Objective

Prepare the execution context for EL0 transition without actually entering EL0.
No user threads, no user code pages, no SVC handlers.

## Completed Scope

### InterruptGuard state preservation (H1)

Fixed the unconditional `DAIFClr` on drop bug:

- `InterruptGuard` now saves the **current** DAIF state at construction (`mrs daif`)
- `Drop` restores the **exact saved** DAIF state (`msr daif, {}`)
- Nested guards work correctly — each reads the current masked DAIF, inner restores
  masked, outer restores original

### context_init user_stack_top parameter (M3)

Extended the API with a `user_stack_top: usize` parameter:

- Kernel threads: `user_stack_top = 0` (SP_EL0 unused in EL1h)
- User threads: `user_stack_top` stored in `ExceptionFrame.sp` → becomes SP_EL0 on eret

### x30 routing (ADR-018)

- Kernel threads: `x30 = entry` (thread_trampoline, as before)
- User threads: `x30 = eret_to_user_stub` (new routing)

### eret_to_user_stub (H2)

Added the SP_EL1-relative synthetic frame trampoline in `arch-aarch64/src/user.rs`:

- `global_asm!` function, ~20 instructions
- Reads synthetic ExceptionFrame at `[SP_EL1 - 272, SP_EL1)`
- Loads `SP_EL0`, `ELR_EL1`, `SPSR_EL1`, restores x0–x30, `eret`
- Follows ADR-018 contract — not yet reachable (no User threads exist)

## Known Limitations

### eret_to_user_stub unreachable

`eret_to_user_stub` compiles but is never executed. It is a dead code path until
M4.5.1 creates the first User thread. Verified by:
- No `ExecutionLevel::User` in any `context_init` call site
- No user stack pages allocated
- No user code pages mapped

### InterruptGuard trait (deferred)

Current `InterruptGuard` stores a `fn(usize)` function pointer in `arch-api`.
This is a mild abstraction leak (arch-api knows about `daif`). Future architectures
(ARMv7, RISC-V) may need a trait-based approach. Deferred to M5/M6 cleanup.
