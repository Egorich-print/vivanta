## Objective

Prove the full EL1→EL0→EL1→EL0 roundtrip: create a user thread via the scheduler,
enter EL0 through `eret_to_user_stub`, handle an SVC exception from EL0, and return
to user mode. No syscall ABI, no user memory validation — only privilege transition.

## What was proven architecturally

### Execution transition (ADR-018)

```
scheduler → context_switch → ret → eret_to_user_stub → eret → EL0
```

The scheduler creates a `Thread` with `ExecutionLevel::User`. `context_init` sets
`x30 = eret_to_user_stub`. `context_switch_asm` ret's into the stub, which reads
the synthetic `ExceptionFrame` at `[SP_EL1 - 272, SP_EL1)`, loads SP_EL0/ELR_EL1/
SPSR_EL1, restores x0–x30, and `eret`s to EL0.

### Exception return (full roundtrip)

```
EL0: mov x0,#42; svc #0
     → save_and_eret_sync saves frame
     → el0_sync_handler prints x0, advances elr
     → eret restores frame
EL0: mov x0,#43; svc #0
     → same path
EL0: b . (infinite loop)
```

Two SVC calls prove the exception state is correctly saved, modified, and restored
— the user thread resumes execution after `svc` with the correct register state.

### Page permissions (ADR-019)

User code: `UXN=0, PXN=1, AP=01` (EL0-executable, EL1-non-executable, EL0 RW)
User stack: `UXN=1, PXN=1, AP=01` (non-executable both)

Even if a kernel bug jumps to a user page, PXN prevents EL1 execution.

## TTBR0-only model (intentional temporary)

Current configuration uses a unified TTBR0 address space (kernel + user mappings
in the same page table). This is documented in ADR-019 as an intentional choice:

- Validated: EL1→EL0 transition, exception return, user execution state
- Deferred: TTBR1 kernel split, ASID-based process switching, independent user AS

The TTBR1 split is planned for a future milestone (M5.x — Kernel Address Space Split).

## Known limitations (not blockers)

| Limitation | Impact | Resolution |
|------------|--------|------------|
| TTBR0-only unified AS | Kernel and user share VA space (no isolation) | M5.x — TTBR1 split |
| No syscall ABI | SVC handler uses only `x0`, no syscall number dispatch | M4.6.1 — syscall ABI |
| No user pointer validation | `el0_sync_handler` trusts user register values | M4.6.x — copy_from_user |
| No user thread lifecycle | User thread loops forever in EL0 after second SVC | M4.6.x — sys_yield + exit |
| No separate process model | Thread and address space are loosely coupled | M4.6.0 — ADR-020 Process Model |
