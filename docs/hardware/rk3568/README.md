# RK3568 — U-Boot / eMMC bring-up

Sub-project of **Vivanta** for the Rockchip RK3568 "NVR" board
(NVR304-32E2 · VS01NMRH VER.A · Barebone RK68/4H/4G/8G).

**Goal:** make the on-board **8 GB eMMC** (FORESEE FEMDNN008G-58A39) visible and
bootable. The stock vendor U-Boot 2017.09 ships no RK3568 SDHCI/eMMC driver, so a
**mainline U-Boot v2026.07** was rebuilt with SPL + external TPL (DDR init) + BL31
and flashed to the board.

## Documents

| File | What it is |
|------|------------|
| `board-info.md` | Hardware reference: SoC, RAM, storage, UART, boot protocol, bring-up status |
| `uboot-emmc-bringup.md` | Runbook: build mainline U-Boot, flash, recover |
| `scripts/build-mainline-uboot.sh` | Reproducible build (SPL + TPL + BL31) → `idbloader.img`, `u-boot.itb` |
| `scripts/flash-serial-mm.py` | Flash over the vendor U-Boot console via `mm.l` (no serial-download cmds) |
| `artifacts/` | Raw session artifacts (rkdeveloptool config/log), for provenance |

Built binaries live (git-ignored) in `vivanta-boot/images/`:
`uboot-rk3568-idbloader-new.img`, `u-boot.itb`, `uboot-rk3568-new-mainline.bin`, …

## Status (2026-09-18)

- ✅ Mainline U-Boot built with eMMC/SDHCI support (strings verified in binary).
- ✅ idbloader (TPL+SPL+BL31) written to SPI NAND offset `0x0` via the vendor shell.
- ⚠️ Boot after flashing not yet confirmed; board observed in **Maskrom** mode.
- ⚠️ macOS USB bulk transfers to the rockusb device fail — see the runbook for
  recovery options (Linux VM / JTAG via FT232H).

See `board-info.md` for the full hardware reference and the current bring-up log.
